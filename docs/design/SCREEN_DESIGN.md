# 画面設計

最終更新: 2026-04-12

---

## 技術方針

| 操作 | 実装方法 | 理由 |
|---|---|---|
| カテゴリ変更・明細削除・金額訂正 | Turbo Stream | JS不要・部分更新 |
| フォーム送信・ページ遷移 | Turbo Drive | 通常の Rails フォーム |
| 手動まとめ入力の行追加 | Stimulus | DOM 操作が必要な最小限の JS |
| グラフ描画・月切り替え | Stimulus + fetch + Chart.js | JSON を受け取って再描画 |

**基本方針**: Turbo Stream でページ遷移なしの部分更新を実現。JS は Stimulus + グラフのみに限定。

**フラッシュメッセージと Turbo Drive**
- Turbo Drive によるリダイレクト後もフラッシュは `<turbo-frame>` の外（body 直下）に配置することで正しく表示される
- Turbo Stream レスポンスでフラッシュを表示する場合は `turbo-stream action="update" target="flash"` で専用領域を差し替える
- フラッシュは数秒後に Stimulus で自動的に非表示にする（`setTimeout`）

## セキュリティ方針

### 認証・認可

| レイヤー | 実装方法 |
|---|---|
| 認証（Authentication） | `before_action :require_login`（ApplicationController）。未ログインは `/sign_in` へリダイレクト |
| 認可（Authorization） | `current_user` スコープで全クエリを絞り込む。他ユーザーのリソースには 404 を返す |

**認可の基本ルール**

```ruby
# ApplicationController に共通ヘルパーを定義
def current_user
  @current_user ||= User.find_by(id: session[:user_id])
end

# 全コントローラで必ず current_user 経由でリソースを取得する
# 例: transactions
@transaction = current_user.transactions.find(params[:id])
# 他ユーザーの id を渡すと ActiveRecord::RecordNotFound → 404
```

- `User.find(params[:id])` のような直引きは禁止
- Import / PaymentMethod / Category / BudgetTemplate はすべて `current_user.xxxxx.find(params[:id])` パターンで取得
- 404 と 403 を使い分けない（リソースの存在を知らせない）→ 他ユーザーリソースへのアクセスは常に 404

### CSRF 対策

- Rails デフォルトの `protect_from_forgery with: :exception` を有効化（ApplicationController）
- Turbo Drive / Turbo Stream は Rails の CSRF トークンを自動付与するため追加対応不要
- Stimulus + fetch を使う箇所（月切り替えなど）は `GET` リクエストのみのため CSRF 対象外
- API エンドポイント（`/transactions/summary`）は JSON のみ返す `protect_from_forgery with: :null_session` を適用

## 「取り込む」ボタンの配置

取り込み操作は `/imports/new` に集約するが、複数箇所からアクセスできる。

```
ダッシュボード   → [CSV取り込み] ボタン    → /imports/new（CSV タブ）
明細一覧         → [CSV取り込み] ボタン    → /imports/new（CSV タブ）。データがない月は特に目立つ
グローバルナビ   → [+ 取り込み ▼] ドロップダウン（常設）
```

### グローバルナビ [+ 取り込み] ドロップダウン

```
[+ 取り込み ▼]
├─ CSV 取り込み       → /imports/new#csv        （CSVファイルをまとめて取り込む）
├─ 手動まとめ入力     → /imports/new#manual_bulk（複数件を表で一括入力する）
└─ 手動1件入力        → /transactions/new        （1件だけサッと入力する）
```

- Turbo Drive によるページ遷移（JS 不要）
- `#csv` / `#manual_bulk` フラグメントでタブを初期選択（Stimulus の `connect()` で読み取り）
- ドロップダウンは Stimulus で開閉。キーボード操作（Esc で閉じる）も対応する

## 入力経路

```
① CSV 取り込み（/imports/new）

## ダッシュボード（/）

当月の収支サマリー。月切り替えで過去月も参照可能。

```
┌─────────────────────────────────────┐
│  ← 2026年3月   2026年4月   2026年5月 →  │← 月切り替え（Stimulus + fetch）
├─────────────────────────────────────┤
│  2026年4月の支出                     │
│  ¥128,400                           │
│                                     │
│  [カテゴリ別円グラフ]                 │← Stimulus + Chart.js
│                                     │
│  未分類 3件 ⚠️  → /transactions     │← クリックで /transactions?month=2026-04&category=uncategorized へ遷移（表示中の月 + 未分類フィルタ）
│                                     │
│  [CSV 取り込み]  [手動入力]           │
└─────────────────────────────────────┘
```

- デフォルト: 当月（アクセス時点の年月）
- 月切り替えは Stimulus + fetch でグラフと合計額のみ再描画（ページ遷移なし）
- グラフデータは `GET /transactions/summary?month=2026-04` → JSON で取得
- URL は **fetch 完了後**に `history.pushState` で `/?month=2026-03` に更新（ブックマーク可能）
  - fetch 中（ローディング中）は URL を変更しない
  - fetch 失敗時も URL は変更しない（エラー表示のみ）

## 取り込み画面（/imports/new）

CSV 取り込みと手動まとめ入力をタブで切り替え。

### タブ1: CSV 取り込み

```
┌─────────────────────────────────────┐
│  [CSV 取り込み] [手動まとめ入力]      │
├─────────────────────────────────────┤
│  支払方法  [楽天カード ▼]            │
│  ファイル  [ファイルを選択]           │
│                                     │
│  ※同じファイルは取り込めません        │
│                                     │
│  [取り込む]                          │
└─────────────────────────────────────┘
```

**取り込み完了後のフロー**
```
成功: → /transactions（取り込んだ明細の月）へリダイレクト
      + フラッシュ「楽天カードの 47 件を取り込みました」
失敗: → /imports/new に留まりエラー表示（再試行可能）
```

### タブ2: 手動まとめ入力

```
┌─────────────────────────────────────┐
│  [CSV 取り込み] [手動まとめ入力]      │
├─────────────────────────────────────┤
│  デフォルト支払方法  [現金 ▼]        │← 全行の初期値。行ごとに変更可
│                                     │
│  日付    店舗名      金額  カテゴリ  支払方法    │
│  [4/08] [ローソン ] [500] [食費▼] [現金▼]    │
│  [4/09] [松屋     ] [900] [食費▼] [PayPay▼] │← 行ごとに変更可
│  [4/10] [         ] [   ] [  ▼ ] [現金▼]    │
│  [+ 行を追加]                ← Stimulus      │
│                                              │
│  [保存]                                      │
└──────────────────────────────────────────────┘
```

- デフォルト支払方法を変更すると、未入力行の支払方法が自動更新される（Stimulus）
- 既に手動で変更した行はデフォルト変更の影響を受けない

**バリデーションエラー表示方式**
- サーバー側バリデーション（行単位）
- エラー行のセルを赤枠でハイライト + 行末にエラーメッセージ（例: 「金額を入力してください」）
- Turbo Stream でエラーのある行だけ差し替える（他の行の入力内容は保持）
- 送信前クライアントバリデーションは実装しない（サーバー1回で完結させる）

**保存完了後のフロー**
```
成功: → /transactions（入力した明細の月）へリダイレクト
      + フラッシュ「3 件を保存しました」
失敗: → /imports/new に留まりエラー行をハイライト表示（Turbo Stream）
```

## 明細一覧（/transactions）

### 絞り込みバー

| 項目 | 内容 |
|---|---|
| 月 | 年月セレクト（デフォルト: 当月） |
| 支払方法 | セレクトボックス |
| カテゴリ | セレクトボックス（「未分類」を含む。ダッシュボードバッジからは未分類が選択済みで遷移） |
| キーワード | 店舗名テキスト検索 |

### 明細テーブル

| 列 | 内容 | 備考 |
|---|---|---|
| 日付 | effective_date | 訂正済みは ✏️ マーク |
| 店舗名 | merchant_name | |
| 金額 | effective_amount | 訂正済みは ✏️ マーク |
| カテゴリ | セレクト即時変更（悲観的更新） | Turbo Stream・未分類は強調 |
| 操作 | 編集・削除 | 削除は Turbo Stream で行を消す |

**カテゴリセレクト変更の更新方針（悲観的更新）**
- セレクト変更 → `PATCH /transactions/:id` を即時送信（Turbo Stream）
- サーバーで保存成功 → Turbo Stream で該当行のカテゴリセルを差し替え
- サーバーで保存失敗 → Turbo Stream でエラーバナーを表示・セレクトを元の値に戻す
- 楽観的更新（先にUIを変えてから保存）はしない。保存完了を待ってからUIを更新する

データなし時：
```
┌─────────────────────────────────────┐
│  2026年4月の明細                     │
│                                     │
│  まだデータがありません               │
│  [CSV を取り込む]                    │
└─────────────────────────────────────┘
```

│  取り込み履歴                        │
├─────────────────────────────────────┤

│  2026-02-05  現金        手動   3件  │[詳細]
│  2026-01-07  楽天カード  CSV   52件  │[詳細]
└─────────────────────────────────────┘
```

### 取り込み詳細（/imports/:id）

```
┌─────────────────────────────────────┐
│  楽天カード / 2026-02-05 / 47件      │
│  rakuten_202601.csv                 │
├─────────────────────────────────────┤
│  [この取り込みをまとめて取り消す]     │← 確認ページへ遷移
└─────────────────────────────────────┘
```

**Import 取り消しの仕様**

| 状態 | 説明 |
|---|---|
| Import レコード | 取り消し後も物理削除しない（RESTRICT FK）。Import 自体は履歴として残る |
| Transaction レコード | 紐づく全件の `deleted_at` に現在日時をセット（ソフトデリート） |
| 再取り込み | `file_hash` の重複チェックは `imports` レコードの存在で行う → 取り消し後も同ファイルの再取り込みは不可（重複扱い）。再取り込みが必要な場合は管理画面で Import を物理削除する |

取り消し操作のフロー：
```
[取り消す] クリック
→ 確認ページ（/imports/:id/cancel_confirm）へ遷移
  「この操作は取り消せません。47 件の明細をまとめて削除します。」
→ [実行] クリック
→ transactions 全件に deleted_at をセット
→ /imports にリダイレクト + フラッシュ「47 件の明細を取り消しました」
```

## 支払方法管理（/payment_methods）

```
┌─────────────────────────────────────┐
│  支払方法                  [+ 追加]  │
├─────────────────────────────────────┤
│  💳 楽天カード   credit             │[編集][削除]
│  💴 現金         cash              │[編集]   ← 自動生成・削除不可
│  📱 PayPay      qr                 │[編集][削除]
│                                     │
│  ── アーカイブ済み ──               │← 折りたたみ表示（デフォルト非表示）
│  💳 旧カード     credit  アーカイブ済み │[復元]
└─────────────────────────────────────┘
```

**削除時の動作（アーカイブ判定）**

```
[削除] クリック
→ サーバー側で transactions の有無を確認
  ├─ 明細なし → ワンクリック確認後に物理削除
  └─ 明細あり → モーダルで説明 + [アーカイブする] ボタン
                「過去 N 件の明細があるためアーカイブします。
                 新しい入力では選択できなくなりますが、過去明細はそのまま残ります。」
→ archived_at をセット（物理削除はしない）
→ 一覧からアーカイブ済みセクションに移動（Turbo Stream）
```

**アーカイブの復元**
- [復元] クリック → `archived_at = NULL` に更新
- 復元後はアクティブリストに戻り、新規取り込み・手動入力で選択可能になる

## エラー時の画面遷移パターン

| エラー種別 | 発生場所 | 表示方法 | ユーザーアクション |
|---|---|---|---|
| CSV 形式エラー（パース失敗） | /imports/new | 同ページにインラインエラー表示（Turbo Stream） | ファイル選び直し |
| 重複ファイルエラー（同一 file_hash） | /imports/new | 同ページにエラー（「2026-01-07 に同じファイルを取り込み済みです」） | 取り込み履歴へのリンクを提示 |
| 手動まとめ入力バリデーションエラー | /imports/new | 該当行をハイライト + エラーメッセージ（Turbo Stream） | 入力修正して再送信 |
| 手動1件入力バリデーションエラー | /transactions/new | 同ページにインラインエラー表示 | 入力修正して再送信 |
| 明細編集バリデーションエラー | /transactions/:id/edit | 同ページにインラインエラー表示 | 入力修正して再送信 |
| 存在しないリソースへのアクセス | 全画面 | 404 ページ | トップへ戻る |
| 他ユーザーのリソースへのアクセス | 全画面 | 404 ページ（403 は返さない） | トップへ戻る |
| 認証エラー（未ログイン） | 全画面 | /sign_in へリダイレクト | ログイン |
| サーバーエラー（500） | 全画面 | 500 エラーページ（「しばらく待ってからお試しください」） | トップへ戻る |

**基本方針**: エラーはページ遷移させず、フォームの近くに表示する（Turbo Stream / Rails バリデーション）。ただし重複ファイルのように「別の画面が正解」の場合はリンクで誘導する。

**404 vs 403 の使い分け**
- 他ユーザーのリソース（`/transactions/999`）へのアクセスも **404** を返す
- 「アクセス拒否」ではなく「存在しない」として扱うことでリソースの存在を明かさない
- Rails の `current_user.transactions.find(params[:id])` は RecordNotFound → 404 に自動マップ

## 危険な操作の確認パターン

全ての破壊的操作に一貫した確認フローを適用する。

| 操作 | 確認方法 | 実装 |
|---|---|---|
| 明細の削除（1件） | ワンクリック確認（「本当に削除しますか？」フラッシュ） | Turbo Stream |
| Import の取り消し（まとめ） | 確認ページへ遷移（件数を明示。「この操作は取り消せません」） | 別ページ遷移 |
| 支払方法の削除（明細なし） | ワンクリック確認（「削除しますか？」） | Turbo Stream |
| 支払方法の削除（明細あり → アーカイブ） | モーダル確認（「過去 N 件の明細があるためアーカイブします。新しい入力では選択できなくなりますが、過去明細はそのまま残ります。」） | Turbo Stream |
| カテゴリの削除 | ワンクリック確認（削除後は明細が未分類になる旨を表示） | Turbo Stream |
| 退会 | 確認文字列の入力（`/account/delete`。「退会する」と入力して送信） | 別ページ遷移 |

**Turbo Stream 確認パターン（例: 明細削除）**
```
[削除] クリック
→ Turbo Stream で確認バナーを表示（「削除しますか？ [確定] [キャンセル]」）
→ [確定] クリックで POST /transactions/:id/destroy
→ 該当行が消える
→ [キャンセル] クリックで元の表示に戻る
```

## レスポンシブ対応方針

**対象デバイス**
- PC（1024px 以上）：フルレイアウト。明細テーブルの全列を表示
- タブレット（768px〜1023px）：PC に準じる
- スマートフォン（〜767px）：フェーズ1ではモバイル最適化は行わない

**フェーズ1のモバイル方針**
- CSS フレームワークは Tailwind CSS（レスポンシブユーティリティ使用可）
- テーブルは横スクロール対応（`overflow-x: auto` のラッパー）で崩れを防ぐ
- 絞り込みバーは縦積みに変わる（`flex-col` on mobile）
- グラフは `max-width: 100%` で収まるサイズに縮小
- モバイル専用レイアウトの作り込みはフェーズ3以降
