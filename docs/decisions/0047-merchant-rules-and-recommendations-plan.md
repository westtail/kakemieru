# ADR-0047: 店舗ルール（明示登録）とおすすめ（履歴集計）による分類

- ステータス: 承認待ち（#152 のマージ前に ADR-0046 を再設計。未決事項は解決済み）
- 関連: [ADR-0046](0046-merchant-classification-learning-plan.md)（本 ADR が supersede）、#152 / PR #156

---

## 背景

ADR-0046（#152）は「明細にカテゴリを付けたら店舗ルールを裏で学習し、次回取込で**黙って自動適用**」する設計だった。実装（PR #156）はレビューまで通ったが、マージ前に方針を見直す。

現行設計の課題:

- **不可視で制御できない**: 学習ルールがユーザーから見えず、誤学習を消す手段もない。
- **勝手に自動適用される**: 1回分類しただけで以降の取込に自動反映され、意図しない分類が起きうる。
- **「意識的に管理したいルール」と「履歴からの推測」が混在**している。

ユーザーは「**自分が認識的に管理する店舗ルール**」を主役にしたい。履歴からの推測は**押し付けず「おすすめ」**として提示し、適用はユーザーが選ぶ。

---

## 決定

分類を **2 層**に分ける。

### Layer 1: 店舗ルール（明示・ユーザー管理）

- `店舗名 → カテゴリ` の確定マッピング。テーブルは `merchant_classifications` を流用。
- **作られ方は「おすすめからの明示登録」のみ**。明細を分類しても**黙ってルール化しない**（分類自体は下記おすすめの集計材料として残る）。手動追加も可。
- 画面はカテゴリページに統合（おすすめ一覧＋登録＋登録済みルールの編集・削除）。

### Layer 2: おすすめ（履歴集計・推奨のみ）

- `transactions` を **店舗 × カテゴリで集計**し、店舗ごとの最頻カテゴリを「おすすめ」として提示（永続テーブルなし＝常に最新）。
- **表示条件は「同じ店舗を 2 回以上分類した実績」**（1 回きりのノイズは出さない）。**件数の多い順**に並べる。
- **すでに店舗ルール登録済みの店舗は集計から除外**（未登録の店舗だけ出す。既登録は再集計不要）。
- **自動適用しない**。ユーザーが登録ボタンで店舗ルールに昇格させる。

### 適用（ルール → 明細）は 2 系統

いずれも **未分類の明細のみ**を対象にする（手動で付けたカテゴリは**上書きしない**）。

1. **取込時に自動適用**: アカウント設定のトグルで ON/OFF。**初期値は OFF**。ON のとき、取り込んだ明細のうちルール一致かつ未分類のものへ自動付与。
2. **「更新実行」ボタン**: 登録済みルールを既存の未分類明細へ一括適用（オンデマンド）。**明細一覧画面と取込完了画面の両方**に設置し、実行後は「N 件を更新しました」を表示する。

### 自動適用と更新実行の導線

- 取込時、設定 ON なら自動適用が走り「取込時に N 件を自動分類しました」と表示。
- その後の**残った未分類**（ルール未一致 or 設定 OFF）に対して、同じ取込完了画面と明細一覧に「更新実行」ボタンを出す。→ 自動と手動は**対象がかぶらず**重複導線にならない。

### QR 決済

- **除外しない**。PayPay 等の決済サービス名も通常の店舗名として扱う。将来ノイズが目立てば除外リストを足せる形にする。

## データモデル

`merchant_classifications`（店舗ルール、ADR-0046 の migration を作り直し）:

| カラム | 役割 |
|---|---|
| `user_id` | 所有者（`ON DELETE CASCADE`） |
| `merchant_name` | 正規化済み店舗名。`(user_id, merchant_name)` UNIQUE |
| `category_id` | 紐づくカテゴリ。複合FK `(user_id, category_id) → categories(user_id, id)` |

- ADR-0046 の `source` / `classified_at` は不要（全ルールが明示登録なので）＝**削除して簡素化**。
- 正規化は従来どおり `CategoryClassifier.normalize`（NFKC + strip + downcase）。

`users` に設定カラムを追加:

| カラム | 役割 |
|---|---|
| `auto_apply_rules_on_import` | boolean, default **false**（取込時自動適用トグル） |

**おすすめ**は永続化しない。集計クエリ（本人・`category_id IS NOT NULL`・`deleted_at IS NULL`・ルール未登録の店舗）で `店舗 × カテゴリ` の件数を出し、店舗ごと最頻カテゴリを提示。`merchant_name` の表記ゆれは正規化して同一店舗に寄せる。

## 主要フロー

```
明細を分類する（手動）
  └─ transactions に 店舗名↔カテゴリ の実績が貯まる（唯一の真実）

カテゴリページを開く
  └─ 未登録店舗を 店舗×カテゴリ 集計 → 「おすすめ: ローソン → 食費（5件）」
       └─ [登録] → merchant_classifications に店舗ルール確定（集計対象から外れる）

ルールを明細へ当てる（未分類のみ・手動分類は保護）
  ├─ 取込時に自動（設定ON時）
  └─ 「更新実行」ボタン（オンデマンド）
```

## #152（PR #156）からの変更点

- **削除**: 分類時に `MerchantClassification.learn_all` を呼ぶ暗黙学習フック（`categorize`/`categorize_all`/`update`）。
- **削除**: 取込時に学習ルールを黙って全適用する挙動。
- **変更**: `CategoryClassifier` を「取込時に**設定ON時のみ**・未分類のみ」ルール適用に用途変更。
- **追加**: カテゴリページのおすすめ集計＋登録、登録済みルールの一覧/編集/削除。
- **追加**: 「更新実行」ボタン（未分類へ一括適用）。
- **追加**: `users.auto_apply_rules_on_import` とアカウント設定トグル。
- **作り直し**: `merchant_classifications` migration（`source`/`classified_at` を落とす）。

## 代替案と却下理由

- **2回以上で自動ルール化**: 確認不要で楽だが「意識的に管理」という主目的に反する（ユーザー選択で却下）。
- **取込時に常に自動適用（初期ON）**: 誤爆時の巻き戻しが面倒。初期 OFF ＋明示適用を採用。
- **おすすめを永続テーブルで持つ**: 集計は軽く、`transactions` から都度算出すれば常に最新。テーブル追加はしない。
- **手動分類も上書き適用**: ユーザーの意図を壊す。未分類のみ対象で保護。

## 解決済みの検討事項

- **おすすめのしきい値/並び**: 同じ店舗を **2 回以上**分類した実績がある店舗のみ、**件数の多い順**。
- **「更新実行」の設置場所と結果表示**: **明細一覧画面と取込完了画面の両方**。実行後に「N 件を更新しました」を表示。
- **取込時自動適用との導線**: 自動適用（設定 ON 時）は取込時に走り、**残った未分類**に対して更新実行ボタンを出す（対象が重複しない）。
