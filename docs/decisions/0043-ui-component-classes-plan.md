# ADR-0043: 共通 UI コンポーネントクラス（ボタン/リンク/フォーム/見出し）

- 日付: 2026-08-25
- ステータス: 承認（スコープ確定）
- 関連: [ADR-0030 Tailwind 採用](0030-tailwind-css-adoption.md)
- 対象 Issue: #52（FE 横断）の第1スライス

---

## コンテキスト

Tailwind の Preflight（ベースリセット）が `<h1>`〜`<h6>`・`<a>`・`<button>` の既定装飾（サイズ・太さ・色・枠）を消す。そのため **Tailwind クラスを付けていない画面**（カテゴリ・取り込み・ログイン・登録・パスワード・アカウント）は、見出しも本文も同じ大きさの黒テキストになり、リンク/ボタンが「押せる場所」に見えない。ユーザーから「取り込みとカテゴリで文字が全部黒く、どこを押せばいいか分からない」と指摘された。

これまで整備済みの画面（明細一覧など）は**長いユーティリティ羅列をインラインで**持っており、同じスタイルの重複・不統一の温床にもなっていた。

---

## 決定

`app/assets/tailwind/application.css` の `@layer components` に**共通コンポーネントクラス**を定義し、見た目の語彙を一元化する。値は既存の整備済みページに合わせる。

- 見出し: `.page-title`（h1）/ `.section-title`（h2）/ `.muted`（補足）
- ボタン: `.btn-primary`（塗り青・主要）/ `.btn-secondary`（グレー・副次）/ `.btn-danger`（赤枠・破壊的）
- リンク: `.link`（青）/ `.link-danger`（赤）
- フォーム: `.field` / `.field-label` / `.field-input`

**Tailwind v4 の制約**: `@apply` でカスタムクラス（例 `.btn`）を合成できないため、各ボタン変種にはベースのユーティリティを直接展開する（`.btn` を作って `@apply btn` はしない）。

未整備画面に上記クラスを適用する（本スライスの範囲）。整備済み画面のインライン記述の置き換えは段階的に別スライスで行う（今回は挙動/見た目を変えない範囲に留める）。

---

## スコープ外

- レイアウト刷新・グローバルナビの現在地ハイライト（#52 の別スライス）。
- 整備済み画面のインライン → コンポーネントクラス全面置換。
- 明細テーブルの金額強調など情報設計の作り込み。
