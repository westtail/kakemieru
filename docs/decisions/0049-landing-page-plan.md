# ADR-0049: 公開ランディングページ（未ログイン時のトップ）

- ステータス: 承認済み
- 関連: #172

---

## 背景

本番の `/`（root → `home#index`）は `require_authentication` により未ログイン訪問者を即 `/sign_in` へリダイレクトする。アプリを紹介する公開トップページが無く、初見の訪問者に何のアプリか伝わらない。ポートフォリオ兼投げ銭運用のため、未ログインでも価値が伝わる公開ランディングページ（LP）を用意する。

---

## 決定

### ルーティング: 同一 URL で出し分け

`/` は据え置き、`home#index` を認証状態で出し分ける。

- **未ログイン** → 公開 LP を表示。
- **ログイン済** → 従来通りダッシュボード（`index.html.erb`）を表示。

ダッシュボードの URL もログイン後遷移（`after_authentication_url` = `root_url`）も変更しない。ログイン後 `/` は認証済のためダッシュボードが表示される。GitHub 等と同じく「同じ入口で、ログイン状態により見せるものを変える」方式。

別案「LP を `/`・ダッシュボードを `/dashboard` に分離」は、ルート移設・ログイン後遷移・ヘッダーのロゴリンク等の変更点が多く、既存挙動への影響が大きいため採らない。

### レイアウト

LP は専用の軽量レイアウト（`layouts/landing.html.erb`）で全幅表示する。application レイアウトの本文幅（`max-w-3xl`）とグローバルナビ（ログイン時のみ表示）は LP に合わないため流用しない。LP 独自のヘッダー（ロゴ＋ログイン/新規登録）とフッターを持つ。

### 内容（標準 LP）

ヒーロー（キャッチコピー＋CTA）＋主要機能 3 点（CSV 自動集計／カテゴリ自動分類／月次ダッシュボード）＋使い方 3 ステップ＋末尾 CTA。CTA は新規登録（`/sign_up`）とログイン（`/sign_in`）へ誘導する。

---

## 非スコープ

- ログイン済ユーザーのダッシュボードの変更。
- 独自ドメイン・OGP・SEO 最適化・アクセス解析（将来検討）。
